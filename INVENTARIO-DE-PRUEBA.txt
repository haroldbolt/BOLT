DATOS QUE TODAVÍA FALTAN

Tener stock no completa los datos comerciales. Solo una presentación tiene
precio, peso y estado suficientes para comprar. Hay 5.650 presentaciones con
precio pendiente, 5.651 con peso pendiente y 372 pertenecientes a productos no
activos; estas categorías se superponen. No se inventaron precios o pesos ni
se reactivaron productos archivados. Puedes completar datos desde el panel de
esta copia para ampliar tus ensayos sin modificar la instalación original.

Se mantienen Turbo hasta 25 minutos, cobertura, límites de peso, franjas,
descuentos y asignación por localidad. Centro sigue fuera de nuevos pedidos
programados aunque tenga existencias en esta copia. El servidor de prueba
bloquea las rutas de Shopify, pagos e integraciones comerciales.

PERSISTENCIA Y RESPALDO

La base original permanece en .bolt-private/operations y la copia independiente
en .bolt-private/inventory-100-test/data. Se creó un respaldo consistente de la
original antes de cargar y se conservaron los 16 pedidos originales intactos.
Las bases, respaldos e informes detallados están excluidos de Git y public/.

Abrir, reiniciar o recargar NO restablece las 100 unidades. Las compras o ajustes
de prueba consumen o cambian cantidades normalmente. Para repetir una carga se
necesita ejecutar explícitamente la utilidad manual con el servidor de prueba
apagado. Nunca se hace desde el arranque ni desde el navegador.

Desde la carpeta del proyecto, con Node y dependencias preparados:
  node --import tsx scripts/prepare-inventory-test.mjs --preview
  node --import tsx scripts/prepare-inventory-test.mjs --apply
  node scripts/start-inventory-test.mjs

La utilidad rechaza rutas operativas, bases enlazadas y cargar mientras esta
copia está abierta. Repetir una carga sin cambios no suma unidades ni crea
movimientos innecesarios. Antes de una nueva carga manual guarda un respaldo
de la copia; no sobrescribe la original.
