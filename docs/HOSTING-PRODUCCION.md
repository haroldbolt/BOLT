# Hosting de BOLT Pets

**Render con disco es compatible con la arquitectura actual de un escritor.** Cloud Run requiere resolver la persistencia y el trabajo en segundo plano antes de admitir pedidos. La decisión de proveedor, región, presupuesto, dominio y fecha de apertura corresponde a Harold.

## Qué versión se puede publicar

La rama de integración de los PR #38 y #39 admite Álamos, Kennedy y Suba en una sola instancia, con Turbo y Programado por sede. El Blueprint usa `BOLT_PILOT_STORE_IDS=HUB_ALAMOS,HUB_KENNEDY,HUB_SUBA`. En un volumen nuevo el lanzador crea `/data/bolt-operacion` sin pedidos. El checkout conserva el bloqueo de recaudo hasta que se configure y autorice su apertura. Cliente y Admin se sirven en `/` y `/admin/nuevo/`. Los paquetes PWA separados también pueden usar la misma API. [Arranque operativo](../deployment/start-pilot.ts) · [Publicación de PWA](./OPERACION-PWA.md)

El lanzador reconoce instalaciones anteriores de Suba mediante `BOLT_PILOT_STORE_ID=HUB_SUBA` y su marcador original. Si detecta esa instalación en un volumen destinado a las tres sedes, detiene el arranque antes de escribir. La migración de ese volumen requiere un respaldo comprobado y una transferencia explícita; activar el Blueprint sobre el disco de la demo mezclaría entornos y el lanzador lo rechaza.

## Render

El Blueprint propone un web service Docker del plan `standard`, una instancia y un disco inicial de 10 GB en `/data`. Son parámetros iniciales que Harold debe revisar según el volumen de fotos, datos, copias y memoria medidos. Render requiere un plan de pago para el disco. El disco se monta en una sola instancia y hay una interrupción durante el reemplazo. El Blueprint lleva publicación automática desactivada. Aplicar el Blueprint por primera vez sí crea el servicio e inicia un despliegue. [Configuración](../render.yaml) · [discos de Render](https://render.com/docs/disks) · [referencia del Blueprint](https://render.com/docs/blueprint-spec)

1. Revisar el PR y los resultados de la imagen en Linux. `bash deployment/check-container.sh` usa Docker, `curl`, `jq` y `openssl` para construir el target `production`, arrancar en un volumen desechable y comprobar el reinicio. Con Render CLI v2.7+ se puede validar `render blueprints validate render.yaml` sin crear recursos. El despliegue operativo debe seleccionar el commit aprobado.
2. Crear un **servicio nuevo** en el entorno correspondiente después de elegir proveedor. Usar el Blueprint en la raíz del repo y confirmar en la vista previa el plan, región, volumen, permisos y coste. `BOLT_IMAGE_STAGE=production` selecciona la etapa operativa durante la compilación. El comando de arranque es `node --import tsx deployment/start-pilot.ts`. Render proporciona `PORT` y el proceso escucha en ese puerto. [Docker en Render](https://render.com/docs/docker) · [Dockerfile de BOLT](../Dockerfile)
3. Verificar que `BOLT_PILOT_VOLUME=/data` esté realmente montado, sea persistente y sea escribible por el usuario de la imagen (`1000:1000`). Mantener `BOLT_REQUIRE_VOLUME_MOUNT=1`. Un error de montaje, permisos o bloqueo requiere revisar el disco y confirmar que no exista un escritor anterior. Preservar datos existentes. Para transferir una instalación, ensayar primero un respaldo restaurable del volumen completo y de la base asociada. [Aislamiento y retorno](./AISLAMIENTO-PRODUCCION.md)
4. Introducir `BOLT_ADMIN_SETUP_TOKEN` de al menos 32 caracteres en el gestor de secretos para inicializar administración. Suministrar individualmente los secretos de cuentas, correo, geocodificación y servicios que efectivamente se habiliten. Las cuentas requieren una base PostgreSQL ya provisionada, rol restringido, conexión TLS y migración explícita. El Blueprint no crea automáticamente una base de clientes. Mantener los secretos de ejecución fuera de Git y de los argumentos de build. Para el mapa web usar la llave pública restringida a los dominios y APIs aprobados. [Variables y migración de clientes](./customer-account/SETUP.md)
5. Validar mediante GET el HTTPS definitivo, el SHA de `/api/v1/health`, las tres sedes en `/api/v1/stores`, simulación deshabilitada en `/api/v1/simulation` y la apertura de Cliente y Admin. Probar el reinicio y persistencia de la instalación. Conservar fuera del disco operativo una copia de recuperación. Registrar el despliegue con `node deployment/tag-release.mjs production "$BOLT_ORIGIN" "$BOLT_SHA"` desde un checkout autorizado, después de verificar el servicio publicado y el SHA de `main`. [Etiquetado verificado](../deployment/tag-release.mjs)
6. Antes de aceptar una compra, confirmar datos operativos de cada sede, horarios, inventario y recaudador autorizado. El hosting por sí solo no activa Rappi Cargo, Wompi, GPS de repartidores ni cobros. Puede verificarse la disponibilidad técnica con las consultas anteriores sin generar un pedido.

## Cloud Run

La imagen escucha el puerto configurado por el entorno y puede recibir tráfico HTTPS detrás del balanceador. El sistema de archivos local de una instancia de Cloud Run es temporal. Montar directamente Cloud Storage con FUSE no satisface el contrato que BOLT requiere para sus bloqueos de escritor y reemplazos POSIX. Fijar una instancia máxima tampoco conserva los datos después de reiniciar o cambiar de revisión. [Contrato de Cloud Run](https://docs.cloud.google.com/run/docs/container-contract) · [limitaciones del montaje de Cloud Storage](https://docs.cloud.google.com/run/docs/configuring/services/cloud-storage-volume-mounts)

Si Harold elige Cloud Run, trasladar pedidos, reservas, catálogo administrativo y auditoría a almacenamiento transaccional, y las fotografías a un almacenamiento de objetos con acceso público o privado según su uso. Separar los trabajadores de despacho y correo o diseñar una ejecución con CPU disponible fuera de las solicitudes, elección de líder y reintentos idempotentes. Antes de habilitar tráfico, validar reemplazo de instancias, restauración, acceso entre cuentas y sedes, concurrencia y consumo. Una alternativa con almacenamiento de red POSIX tendría que demostrar en esa infraestructura las garantías de montaje, escritura, bloqueo y recuperación que BOLT necesita. [Plan de migración](./AISLAMIENTO-PRODUCCION.md) · [asignación de CPU en Cloud Run](https://docs.cloud.google.com/run/docs/configuring/billing-settings)

## HTTPS, orígenes y proxy

| Configuración de ejecución | Valor que debe verificar la ingeniera |
| --- | --- |
| `BOLT_PUBLIC_ORIGIN` | Origen HTTPS público exacto del backend, sin ruta ni barra final. Si se omite, el proceso utiliza `BOLT_CUSTOMER_ORIGIN` y después `RENDER_EXTERNAL_URL`. Al activar cuentas, el origen del flujo de autenticación debe coincidir con el que sirve esas páginas. |
| `BOLT_TRUSTED_PROXY_CIDRS` | Direcciones o subredes IPv4/IPv6 separadas por comas, verificadas para los saltos de proxy de esa instalación. El ingreso debe sobrescribir el protocolo y preservar el Host canónico. Limitar también el acceso por red al contenedor. Un rango de salida de Internet del proveedor no identifica el proxy de ingreso. |
| `BOLT_PWA_ORIGINS` | Opcional. Orígenes HTTPS exactos de interfaces web separadas que necesiten CORS en `/api/v1`. Una PWA servida por este mismo backend no requiere añadir un origen. Los endpoints de sesión de clientes continúan asociados a su propio sitio. |

El servicio admite TLS directo o la indicación `X-Forwarded-Proto: https` de un salto autorizado. Valida la cabecera Host frente al origen publicado, ignora los hosts reenviados y solo devuelve HSTS al aceptar el transporte seguro del host canónico. El formulario de retorno de Apple conserva su excepción de origen exclusiva de su callback y la validación de estado de Better Auth. La sonda GET/HEAD de salud admite HTTP interno. Por eso una sonda verde por sí sola no comprueba la cadena TLS del usuario: verificar mediante HTTPS que catálogo, Cliente y Admin responden a través del dominio canónico y que el origen ajeno carece de permiso. [HTTPS de Render](https://render.com/docs/web-services) · [cabeceras del balanceador de Google](https://docs.cloud.google.com/load-balancing/docs/https) · [configuración de Express detrás de proxies](https://expressjs.com/en/guide/behind-proxies.html)
